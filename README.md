# Encyclopedia of Benchmarks

A cross-platform collection for comparing algorithm implementations across programming languages. TheAlgorithms repositories are the initial discovery source. When an algorithm has no implementation in one of our target languages, we will write one and record it as a port.

## Goals

- Catalog algorithms and implementations across languages.
- Compare implementations only when they solve the same problem with the same input and output semantics.
- Keep a portable baseline for every benchmark. Default code must not depend on Intel-only instructions or x86-only compiler flags.
- Record enough source, build, machine, and workload details to reproduce a result.
- Preserve attribution and license information for any code taken from an upstream project.

## Layout

The current language folders are `c`, `c3`, `cpp`, `elisa`, `nim`, `odin`, `rust`, `v`, and `zig`. Algorithms are grouped by the first letter of the algorithm name, for example `rust/l/linear_search.rs`; names beginning with a digit go under `0-9/`. Workloads and result files use the same organization, such as `benchmarks/l/linear_search/` and `results/l/linear_search/`.

The first source-path inventory is in [CATALOG.md](CATALOG.md) and [`catalog/algorithm-candidates.json`](catalog/algorithm-candidates.json). One hundred twenty-one unique reviewed benchmarks now have shared contracts, workloads, and portable implementations across all nine target languages: nine search algorithms, thirty-one sorting algorithms, thirty-three scalar algorithms, twenty-one conversion algorithms, eight graph algorithms, one array algorithm, one tree traversal, one binary-search-tree operation algorithm, two combinatorial algorithms, five dynamic-programming algorithms, three string algorithms, one postfix-expression evaluation algorithm, one stack-operation algorithm, one queue-operation algorithm, one two-stack queue algorithm, one linked list operation algorithm, and one doubly linked list operation algorithm. They cover 164 reviewed filename candidates, including aliases for `edit_distance`, `0_1_knapsack`, `absolute_value`, `catalan`, `catalan_numbers`, `catalan_sequence`, `catalannumber`, `coin_change_topdown`, `eratosthenes_sieve`, `odd_sieve`, `prime_sieve`, `prime_sieve_eratosthenes`, `sieve2`, `sieve_er`, `check_prime`, `is_power_of_two`, `is_prime`, `lcs`, `letter_combination`, `edit_distance`, `levenshtein`, `levenshteindistance`, `perfect_number_checker`, `perfectnumber`, `prime`, `zero_one_knapsack_problem`, `longest_increasing_subsequence_nlog_n`, `longest_increasing_subsequence_nlogn`, `longest_increasing_subsequence_o_nlogn`, `longest_increasing_subsequence_using_binary_search`, `longestincreasingsubsequence`, `longestincreasingsubsequencegreedy`, `decimal_to_any`, `int_to_base`, `base_x`, `arbitrary_base`, and `int_to_negative_binary_base`, `bogo_sorter`, `bogosort`, `greatest_common_divisor`, `least_common_multiple`, `towers_of_hanoi`, and `singly_linked_list` aliases `linked_list`. See each algorithm guide under [`benchmarks/`](benchmarks/) and the [benchmarking instructions](BENCHMARKING.md).
