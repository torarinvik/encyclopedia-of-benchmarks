# Sparse supernodal Cholesky

This in-progress profile factors a sparse symmetric positive-definite matrix using a supplied filled pattern and consecutive supernodes. The numerical implementation will factor each dense diagonal block, solve the panel below it, and scatter the panel's trailing update into later sparse storage. Symbolic ordering and analysis are outside the timed operation.

The proposed input is `[n, s, boundaries[s+1], row_masks[n], lower_triangle[n*(n+1)/2]]`. `1 <= n <= 8`, `1 <= s <= n`; boundaries start at zero, end at `n`, and increase strictly. Bit `j` of row mask `i` denotes factor position `(i,j)` and is allowed only for `j <= i`; every diagonal bit must be present. Lower-triangle input values are signed integers scaled by `1/1000`, in row-major triangular order and bounded to ±1,000,000. Entries absent from the pattern must be zero.

For every column, all pairs of its structurally present lower rows must have their mutual lower-triangular position in the supplied pattern. Inside each supernode its diagonal block must be dense, and every row below the block must contain either all its columns or none. These checks ensure the numerical updates have storage and panels are rectangular. Pivots must be strictly positive. Invalid input returns `-1`; a null or short output buffer returns `-2` only after input validation.

The numerical work is bounded by O(n³) time and O(n²) storage in the dense worst case; sparse factor entries are stored compactly, while the bounded position map uses O(n²) space. Pattern validation also takes O(n³) time in the worst case.

Output is the complete lower triangle of `L`, including structural zeros, as little-endian binary64 words in row-major triangular order. The result is its byte length. The maximum frame has 55 i64 words, the maximum output has 288 bytes, and a parseable malformed frame may have 56 words. Compare binary64 output with absolute and relative tolerances of `1e-9`.

The primary oracle independently validates the frame and performs right-looking block and panel updates; a dense scalar reference oracle separately validates and factors it. The workload includes diagonal, sparse-chain, multiple dense supernodes with signed panel entries, maximum-size, malformed-pattern, late pivot failure, and output-buffer cases. All ten language ports use compact storage for structurally present factor entries and are registered in the byte-output suite. This is a bounded numerical-factorization profile, not a reproduction of the SPLASH-2 scheduler. The mathematical approach is informed by [Karsavuran et al.](https://arxiv.org/abs/2409.13090); the article is CC BY-NC-ND 4.0 and no text or code has been copied. The package and registration have not been executed.
