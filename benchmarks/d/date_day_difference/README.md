# Date Day Difference

Ports the date-distance operation from the pinned [TheAlgorithms/JavaScript implementation](https://github.com/TheAlgorithms/JavaScript/blob/5c39e87a9a31f279c60f830ad74a845e4788a517/Conversions/DateDayDifference.js), together with its pinned [date parser](https://github.com/TheAlgorithms/JavaScript/blob/5c39e87a9a31f279c60f830ad74a845e4788a517/Timing-Functions/ParseDate.js), [month-length helper](https://github.com/TheAlgorithms/JavaScript/blob/5c39e87a9a31f279c60f830ad74a845e4788a517/Timing-Functions/GetMonthDays.js), and [leap-year rule](https://github.com/TheAlgorithms/JavaScript/blob/5c39e87a9a31f279c60f830ad74a845e4788a517/Maths/LeapYear.js).

The `i64_array_scalar` ABI packs two date strings into one sequence of ASCII code values, separated by `|`: `d/m/yyyy|d/m/yyyy`. Each day and month has one or two decimal digits, each year has exactly four digits, and slash is the only date separator. Years 0000 through 9999 are accepted. Dates use the Gregorian month lengths and leap rule: divisible by 400, or divisible by 4 but not 100. The result is the absolute difference between the source's serial day values. Malformed packed input and invalid dates return -1, mapping the source parser's exceptions into the scalar ABI.

Inputs contain 17 through 21 values. The ordinal expression is `365*(year-1) + floor((year-1)/4) - floor((year-1)/100) + floor((year-1)/400) + day + floor((367*month-362)/12) + adjustment`, where adjustment is 0 for January/February, -1 for later months in leap years, and -2 for later months otherwise. The year-zero terms use mathematical floor division, matching JavaScript `Math.floor`. Runtime is O(1) for the bounded date strings. The pinned parser regex can accept a final line terminator because JavaScript `$` may match before it; this benchmark intentionally requires strict packed ASCII formatting, so that parser edge is outside the contract.
