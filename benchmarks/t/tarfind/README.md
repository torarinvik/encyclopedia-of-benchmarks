# Embench-IoT TAR header filename search

This package ports the filename lookup kernel from Embench-IoT's tarfind
benchmark. It scans the archive records in order and returns the first record
whose filename exactly matches each query. The input models only the filename
field from each TAR header: the upstream benchmark creates header-like records
and does not inspect payloads or the other header fields.

## Contract

The i64_array_bytes_output input is packed as:

[record_count, query_count, name_length, name_byte..., ...records..., name_length, name_byte..., ...queries...]

There are 1–35 records and 1–5 queries. Each filename is 5–39 uppercase ASCII
letters, matching the lengths and alphabet generated by the pinned benchmark.
The record and query fields are each length-prefixed; no padding or trailing
values are allowed. For each query, the output contains the zero-based index
of the first exact filename match. Byte 255 means the name was not found.
Valid input returns the number of queries, which is also the number of output
bytes. Malformed input returns -1; a null output pointer or capacity smaller
than the query count returns -2 without writing output.

The parser accepts at most 1,602 signed-i64 input values and writes at most
five bytes. The largest input has all 35 records and five queries at the
39-character filename limit.

The oracle and [workload.json](workload.json) include first, middle, and
last matches, duplicate names, a missing name, maximum record/query counts,
maximum filename lengths, malformed framing and bytes, null pointers, and
output-capacity failure. The oracle is
[tarfind_oracle.py](../../tarfind_oracle.py).

## Provenance and rights

The source is
[src/tarfind/tarfind.c](https://github.com/embench/embench-iot/blob/de24bdf561f4eaad7f37685641fa301f2b8b4bc3/src/tarfind/tarfind.c)
at Embench-IoT commit
[de24bdf561f4eaad7f37685641fa301f2b8b4bc3](https://github.com/embench/embench-iot/commit/de24bdf561f4eaad7f37685641fa301f2b8b4bc3).
The file describes the TAR-search benchmark as created by Julian Kunkel for
Embench-IoT and declares SPDX-License-Identifier: MIT. Its header does not
specify a copyright year. The repository-level COPYING is GPL-3.0; this
package follows the target source file's explicit MIT declaration and retains
the MIT notice in [LICENSE.txt](LICENSE.txt). The language implementations
are independently written bounded ports; they do not copy or translate the
upstream source.

The source benchmark uses 35 generated names and five searches beginning in
the middle of the record list. This contract accepts explicit bounded names
and queries so the same linear scan can be checked for early, late, duplicate,
and absent matches across all nine ports.
