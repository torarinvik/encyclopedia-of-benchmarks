# Bogo sort

## Contract

Sort a mutable sequence of signed 64-bit integers in ascending order, in place. Empty and single-element inputs are unchanged. The benchmark contract caps inputs at six elements because bogo sort has factorial expected work and an unbounded loop.

Each call first checks whether the input is already sorted. Otherwise it repeatedly applies Fisher–Yates shuffles from the last element down to index one until the array is sorted. To make runs reproducible across languages and platforms, every call resets the same unsigned 32-bit linear-congruential generator state to `2654435769`. Each random step updates `state = (1664525 * state + 1013904223) mod 2^32`; the selected index is `(state / 65536) mod (index + 1)`. This defines one shared shuffle stream and avoids platform-specific `rand()` behavior, system entropy, and clock-based seeds.

The entry point has the scratch-free sorting ABI:

```c
void bogo_sort(int64_t *values, size_t length);
```

## Workload

[`workload.json`](workload.json) uses lengths zero through six and values generated by `(index * 4) mod 7`. This deliberately small workload is suitable for checking and timing the algorithm's behavior; it does not support extrapolating performance to larger arrays. The portable C runner prepares a `qsort` reference outside timing, restores the same input before each sample, times one sort call, and checks the full sorted output.

The upstream implementations use different shuffle APIs and random seeds, including C's `rand()`, C++'s standard random facilities, and a time-seeded PCG in Rust. The local contract fixes the random stream so every language sorts the same workload reproducibly.
