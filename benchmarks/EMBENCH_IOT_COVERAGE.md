# Embench-IoT source inventory and coverage

This crosswalk audits every benchmark source directory at Embench-IoT commit [`de24bdf561f4eaad7f37685641fa301f2b8b4bc3`](https://github.com/embench/embench-iot/tree/de24bdf561f4eaad7f37685641fa301f2b8b4bc3/src). A local package is a bounded algorithm profile and does not claim to reproduce the Embench harness, scale factors, complete datasets, or score. All local packages document their source pin, profile limits, and rights. Embench source files generally declare `GPL-3.0-or-later`; `md5sum` declares MIT. The wikisort source also says the original WikiSort was placed in the public domain.

## Duplicate and exclusion decisions

- `matmult-int`, `md5sum`, `nettle-sha256`, and `nettle-aes` reuse algorithms already covered by local matrix multiplication, MD5, SHA-256, and AES-256 block encryption/decryption packages. They do not receive parallel packages solely for a different launcher, implementation, key schedule, or fixed data profile.
- `ud` is classified with LU solve, not as a second decomposition benchmark: it factors a matrix and applies forward and backward substitution to solve the system, the same operation represented by `lu_elimination`.
- `sglib-combined` is an aggregate stress benchmark over common structures and sorting operations. Its individual algorithm classes already have local coverage, so the aggregate is not counted as a new atomic algorithm.
- `edn` is a multi-kernel source; only its four distinct measured kernels have packages. The `mac` helper is a combined dot-product/energy reduction rather than a separate algorithm core; the FIR and `fir_no_red_ld` helpers both compute direct convolution windows, already represented by [`convolution`](c/convolution/README.md), and the latter's unrolled two-output form is a load-reuse variant. The generic `fir` helper is not called by the source benchmark body. The `codebook` body contains an empty loop after its calculation was removed. Other helper routines not invoked by the benchmark body are not separate candidates.

The crosswalk records source correspondence and bounded scope only. No runtime-correctness or execution claim is made here.
