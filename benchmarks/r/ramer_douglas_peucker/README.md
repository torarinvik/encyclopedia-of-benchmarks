# Ramer–Douglas–Peucker polyline simplification

This package covers the shared observable behavior of the pinned Python and Rust implementations on a bounded common domain. Python measures clamped distance to the segment; Rust measures distance to the infinite line. The input contract requires every interior point to project onto every segment formed by any ordered pair of input points. The validator also evaluates both pinned distance formulas for every original chord and requires them to select the same first maximum and make the same `maximum > epsilon` decision. Every recursive subproblem uses one of these chords, so both implementations retain the same indices. It excludes repeated points and zero, underflowed, or non-finite chord lengths, which the Rust source does not handle safely.

## Contract

The `float64_slice_io` input is `[point_count, epsilon, x0, y0, x1, y1, ...]`. It accepts 0–12 points, finite coordinates in `[-100,100]`, and finite `epsilon` in `[0,100]`. For three or more points, every pair of points must be distinct, and for every triple of indices `i < k < j`, the orthogonal projection of point `k` onto the line from point `i` to point `j` must lie within the closed segment. Then, for each original chord, the validator computes the maximum distance and first maximum index using both the Python clamped-coordinate plus `hypot` formula and the Rust line-equation formula. Inputs are accepted only when both formulas choose the same first maximum and agree whether it exceeds epsilon.

Both sources select the first interior point attaining the maximum distance, split only when that maximum is strictly greater than `epsilon`, and preserve the original point order. Inputs with fewer than three points are returned unchanged. Output is `[result_count, x0, y0, ...]`; invalid framing, bounds, repeated points, unsafe chord lengths, out-of-segment projections, or differing source split decisions return `-1`. Insufficient output capacity returns `-2` without writes.
