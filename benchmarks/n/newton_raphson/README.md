# Newton–Raphson

This package benchmarks a bounded positive-root use of Newton–Raphson for `f(x) = x² - radicand`. The input is exactly `[radicand, start_quarters]`: `radicand` is 2..4 and `start_quarters` is 4..8, giving the initial guess `x₀ = start_quarters / 4`. The positive initial guess keeps every derivative nonzero and selects the positive root. Invalid lengths or values return `-1e300`.

The grouped sources are generic Newton APIs, but their native derivative and stopping controls differ, so this package does not claim byte-for-byte parity across their generic APIs: [TheAlgorithms/Python](https://github.com/TheAlgorithms/Python/blob/e1a2a8b016001309a73d5fec4818c35cca139795/maths/numerical_analysis/newton_raphson.py) approximates the derivative by a centered finite difference and checks the residual before each update; [TheAlgorithms/R](https://github.com/TheAlgorithms/R/blob/f65344fabeea0ae33c1ca321af709447c1a8a4c2/mathematics/newton_raphson_method.r) takes a supplied derivative and stops when the step distance is below its tolerance; [TheAlgorithms/Rust](https://github.com/TheAlgorithms/Rust/blob/fed66cb0c74c4a939ec5163648458a8c2b46fd4c/src/math/newton_raphson.rs) takes a supplied derivative and performs a fixed number of updates. The normalized source profiles use this same quadratic and finite domain with bounded controls: Python uses finite-difference step `1e-6`, residual threshold `1e-10`, and at most 8 iterations; R uses step-distance tolerance `1e-8` and at most 8 iterations; Rust performs 8 updates. Each profile returns the positive root within `1e-8` on all valid inputs. The nine compiled language ports implement a normalized eight-update Newton recurrence under the same input/output contract. All valid results are compared with the mathematical positive root using absolute tolerance `1e-8`.

The domain has only 15 valid inputs. Runtime and auxiliary space are O(1), with at most eight Newton updates.
